1. Contexte Métier & Vision du Produit

⚠️ Problématique du Secteur BTP

Le secteur du Bâtiment est encadré par une documentation technique immense et normative (DTU, Eurocodes, RE2020, fiches CSTB) :

  • Masse documentaire : Manuels de 300+ pages inadaptés à une consultation rapide sur chantier ou en formation.
  • Risque d'hallucination : Les LLM grand public inventent des formules de calcul ou des coefficients erronés.
  • Obsolescence & Liens 404 : Les ressources web évoluent ou disparaissent, brisant la confiance technique.

🎯 La Solution BUILD AI

BUILD AI est une plateforme logicielle souveraine, locale et sécurisée :

  • RAG Hybride (BM25 + Vecteurs) : Zéro approximation sur les sigles, normes et termes métier pointus.
  • Traçabilité Totale : Chaque réponse cite sa source avec lien direct vers le fichier PDF exact hébergé en local.
  • Multi-Agents Autonomes : Génération automatique de cours pédagogiques complets téléchargeables en Word (.docx).
  • Calcul Local Optimisé : Inférence sur GPU grand public (< 4 Go VRAM) avec bascule CPU/RAM automatique.

4. Architecture Détaillée du Moteur RAG Hybride

Le RAG purement vectoriel échoue souvent sur le BTP car les requêtes contiennent des codes normatifs précis (ex: "DTU 13.12", "C25/30", "aciers HA FE 500") que les vecteurs denses peuvent noyer. BUILD AI combine recherche lexicale et sémantique dans un pipeline équilibré.

+---------------------------------------------------------------------------------------------------------+ | REQUÊTE UTILISATEUR : "Comment calculer la descente de charges ?" | +---------------------------------------------------+-----------------------------------------------------+ | +------------------------v------------------------+ | Prétraitement & Lemmatisation spaCy | | (fr_core_news_sm + Regex Markdown) | +------------------------+------------------------+ | +--------------------------------+--------------------------------+ | | +------------------v------------------+ +-----------------v-------------------+ | BRANCHE LEXICALE : BM25 | | BRANCHE SÉMANTIQUE : DENSE | | Elasticsearch (Index BTP) | | Qdrant (Vecteurs d'embeddings) | | Score BM25 normalisé | | Score de similarité cosinus | | Poids configurable (w_bm25=0.5) | | Poids configurable (w_vec=0.5) | +------------------+------------------+ +-----------------+-------------------+ | | +--------------------------------+--------------------------------+ | +------------------------v------------------------+ | FUSION DES SCORES & RERANKING | | Score_Final = w_bm25*S_bm25 + w_vec*S_vector | | Filtrage des Top-K Chunks les plus pertinents | +------------------------+------------------------+ | +------------------------v------------------------+ | RÉSOLUTION DES SOURCES & CITATIONS PDF | | Remplacement [1] -> Lien pérenne File Server | +------------------------+------------------------+ | +------------------------v------------------------+ | GÉNÉRATION STREAMING LLM (Ollama) | | Prompt Expert BTP + Contexte + Thinking Box | +-------------------------------------------------+

🔍 Lemmatisation Française (spaCy)

Le module hybrid_retriever.py nettoie le markdown et applique une lemmatisation complète via spaCy (fr_core_news_sm). Ainsi, "fondations superficielles" et "fondation superficielle" sont ramenées à leur racine commune pour maximiser le rappel.

📄 Traçabilité & Zéro Liens 404

Les sources externes scrapées sont conservées localement dans storage/raw_data/. Grâce au fichier de correspondance global_hashes.json, chaque citation [1] générée par le LLM est automatiquement liée à l'URL locale du PDF officiel.

5. Pipeline d'Ingestion & Préparation du Corpus Documentaire

🌐 1. Scraping Ciblé

Collecte automatisée via des scripts Python spécialisés (scrapping/scrape_article.py, scrape_btp_cours.py) extrayant articles de génie civil, calculs de structures et documents techniques PDF.

🧹 2. Filtrage & Nettoyage

Suppression des bannières, menus, publicités et contenus parasites. Extraction textuelle des PDF et conservation des métadonnées (titres, dates, auteurs, chapitres).

✂️ 3. Chunking & Indexation

Découpage sémantique en morceaux de 500 à 1000 caractères avec chevauchement. Vectorisation avec embeddinggemma et insertion simultanée dans Elasticsearch et Qdrant.

💡 Performance d'Indexation
Le corpus rassemble plus de 2 Go de documents techniques (manuels de coffrage, dimensionnement d'ouvrages d'art, mécanique des sols, fiches DTU). La double indexation permet d'atteindre un temps de recherche moyen inférieur à 150 ms avant transmission au modèle de langage.

6. Moteur Multi-Agents de Génération Automatique de Cours

Pour créer des cours complets et structurés sur des sujets techniques (ex: "Les types de fondations et leur mise en œuvre"), BUILD AI mobilise trois agents autonomes spécialisés orchestrés par la classe MultiAgentOrchestrator.

1. Retriever Agent

Rôle : Collecteur de savoir métier.

Décompose le sujet en plusieurs requêtes ciblées (définitions, calculs, pathologies, normes). Interroge le moteur hybride et assemble la base brute de connaissances.

2. Enhancer Agent

Rôle : Critique & Enrichisseur.

Évalue la complétude des connaissances, identifie les zones d'ombre ou lacunes techniques et lance des boucles itératives de recherche ciblée pour combler les manques.

3. Generator Agent

Rôle : Rédacteur Pédagogique.

Structure le syllabus, rédige les modules détaillés, intègre les formules et génère les fichiers finaux aux formats Markdown et Microsoft Word (.docx).

⚡ Innovation Technique : Streaming Temps Réel avec "Thinking Box" et Heartbeats
La génération d'un cours complet prend entre 45 et 120 secondes en local. Pour éviter que le navigateur ou LibreChat ne coupe la connexion (timeout HTTP), BUILD AI a conçu une architecture réactive à trois piliers :
  • Capture non bloquante : StreamingPrintCapture intercepte en direct les logs console émis par chaque agent.
  • Heartbeats SSE (10s) : async_stream_wrapper_with_heartbeat maintient la connexion ouverte en envoyant des pulsations régulières.
  • Thinking Box : L'utilisateur voit le raisonnement des agents défiler en temps réel dans l'interface avant de recevoir le document final téléchargeable.

8. Gestion de l'Infrastructure Matérielle (GPU NVIDIA vs CPU/RAM)

⚙️ Résolution Native du Déploiement Matériel Hétérogène

Un défi majeur du projet était de concilier une machine de développement équipée d'un GPU NVIDIA RTX 3050 (4 Go VRAM) avec des machines d'évaluation ne possédant que du CPU et de la RAM :

  • Contrainte Docker : Déclarer driver: nvidia dans docker-compose.yml fait crasher le démarrage sur les PC sans GPU. Le supprimer bride l'exécution sur GPU.
  • Solution mise en place : Le fichier docker-compose.yml principal est universel (CPU/RAM). Un fichier local docker-compose.override.yml (exclu de Git) active l'accélération matérielle sur la machine GPU.
  • Expérience développeur : Sur toutes les machines, la simple commande standard docker compose up -d fonctionne immédiatement sans erreur.
